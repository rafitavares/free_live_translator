# Church Cap v0.7.6 Draft Release Notes

Status: development; first deterministic Service Context implementation available for testing.

## Current branch summary

Church Cap v0.7.6 begins from the v0.7.5 production baseline and now includes the first optional, temporary Service Context workflow for pre-service testing.

## Included in the current v0.7.6 source copy

- Advance application defaults, environment examples, browser cache identifiers, tests, and current documentation to v0.7.6.
- Retain the v0.7.5 caption, translation, translated-audio, Operator navigation, Congregation, privacy, diagnostics, storage, updater, and security behaviour.
- Add a detailed Service Context plan covering sermon notes and full scripts, deterministic extraction, optional local-model assistance, operator review, Bible-reference handling, temporary storage, performance limits, evaluation, and staged rollout.
- Add Dashboard → Service Context for optional preparation before a service: paste notes or choose a bounded UTF-8 `.txt`/`.md` file, review locally extracted terms and Bible references, add explicit corrections, and approve them for the next caption run. Mark the feature **Beta** and **Optional** in its menu, live-service shortcut and page, with a round information control that warns operators about possible accuracy, resource and latency regressions and requires pre-production testing.
- Keep raw notes out of retained state. Approved context is memory-only, locks at caption start, becomes inactive at stop, expires after four hours, and must be explicitly re-armed before reuse.
- Make deterministic temporary corrections the default Service Context live path, without changing Whisper's normal prompt or hotwords. Add a separate, off-by-default experimental recognition option capped at two selected terms and eight additional prompt tokens. Full Bible-reference phrases stay out of the recognition prompt.
- Add privacy-safe Service Context mode, hint-count, added-token, reference-count and correction-count fields to retained service measurements so identical-audio comparisons can isolate the experimental recognition cost without retaining note or term text.
- Precompile operator-approved temporary corrections before the service, then apply an always-on deterministic English Bible-reference formatter after the layered glossary. For example, “first Corinthians chapter thirteen verse four” becomes `1 Corinthians 13:4` even when no notes were uploaded.
- Expand the built-in caption-safety dictionary with conservative plurals, inflections and spaced compound variants commonly produced by speech recognition. Preserve ambiguous biblical words such as “hell”, “ass” and “cock” to avoid censoring legitimate sermon wording; churches can continue adding local entries in `config/profanity_filter.txt`.
- Add authenticated installation progress for text-translation and spoken-language resources. The Operator UI shows one overall percentage bar with the current phase; spoken-language installs also show compact progress circles for each selected voice package. Known voice downloads report actual bytes, while dependency and model-conversion phases are clearly identified as stage estimates.
- Refine the paired Service Leader page for on-the-go mobile use. Live controls remain immediately available, while health, audio, congregation access, languages, and warned exports use a single-open grouped menu. Add connection freshness, a pending-language-request badge, and a cross-platform audience-link panel that uses the native Apple/Android share sheet where available and retains Copy, Text and Email fallbacks on local HTTP.
- Reuse the exact Operator Service Leader and Diagnostics icon language for Service and Tools, remove the extra selected-option edge stripe, and improve light-theme contrast for health states, menu descriptions and selected tasks.
- Display storage and optional model estimates in familiar decimal MB and GB units throughout the Operator UI and spoken-language documentation.
- Prevent temporary Windows locks on the optional installer progress JSON from cancelling an otherwise healthy spoken-language download. Progress writes now use unique temporary files, short replacement retries and a best-effort fallback; progress reporting can no longer terminate the installer.
- Replace operating-system emoji flags with a bundled, MIT-licensed `flag-icons` SVG subset across the audience, Operator and Service Leader language controls. This fixes missing flags on Windows while keeping Linux and macOS offline and deterministic; language-code badges remain as a load-failure fallback.
- Harden Safari audience sessions by clearing obsolete caption ping timers, releasing caption/audio WebSockets and media resources when a page is suspended, reconnecting on restore or network recovery, and forcing viewer HTML and refreshed static asset versions past stale browser caches.
- Add a shared audio-callback watchdog for Faster Whisper and standard Whisper. If an input remains marked open but stops delivering callbacks for three seconds, Church Cap closes and reopens only the audio stream, clears the stale rolling buffer, retains the loaded Whisper/CUDA model, and retries failed reopens with bounded backoff. Operators receive a recovery notice, while privacy-safe service metrics and logs count stalls, successful restarts and failed attempts.
- Update the implementation status, acceptance framework, roadmap and blueprint for the v0.7.6 development cycle. Retain the superseded 6 August Word action plan under an explicitly archived filename for historical context only.
- Confirm the current automated baseline: 321 Python regression tests, Python compilation, local Markdown-link validation, JSON and POSIX shell syntax, a high-severity Bandit scan, and an installed-environment dependency audit all pass.

## Remaining before release acceptance

- Running an optional lightweight local extraction model before a service.
- Corpus-based accuracy and false-insertion evaluation across varied writing styles, speakers and hardware.
- Full privacy, resource-contention, browser, appliance, Windows and Linux acceptance evidence.

The deterministic workflow is available for development testing, but should not be advertised as release-ready until the remaining acceptance evidence is complete.

## Retained v0.7.5 capabilities

v0.7.5 introduced optional local audio for finalized translated captions, Tigrinya in the Recommended translation bundle, grouped Operator submenus, improved Linux CUDA checks, and clearer audience-network setup. v0.7.6 retains those capabilities; text captions remain the primary path and never wait for speech synthesis.

AI-generated captions, translations, speech, and future context suggestions can contain mistakes and are not an authoritative record. Test the intended languages, voices, devices, audio route, privacy controls, Wi-Fi capacity, and target hardware before a live service.
