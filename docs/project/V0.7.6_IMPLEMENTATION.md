# v0.7.6 Implementation Status

Version: v0.7.6

Church Cap v0.7.6 starts from the completed v0.7.5 baseline. The application version, updater metadata, client cache identifiers, tests, setup guidance, legal notices, and versioned project documents have been advanced to `0.7.6`. Existing caption, translation, presentation, Service Leader, Operator, diagnostics, security, updater, and optional translated-audio behaviour is retained.

The principal feature under development for this release is **Service Context**: an optional, per-service workflow that turns sermon notes or a full script into a small, operator-reviewed recognition aid. The deterministic workflow, review UI, lifecycle and live recognition integration are implemented. Corpus evaluation and multi-platform acceptance remain required before it is treated as release-ready.

## Service Context workstreams

1. **Input and privacy boundary — implemented** — pasted text and UTF-8 `.txt`/`.md` notes are accepted only while captions are stopped, with conservative byte/text/line limits and clear temporary-data messaging.
2. **Deterministic extraction first — implemented** — names, distinctive/repeated terms, headings and Bible references are suggested without requiring another model.
3. **Optional local model assistance** — allow a small local model to suggest structured terms before a service, subject to resource checks, a strict schema, timeouts, and deterministic validation. It must unload before Whisper starts.
4. **Operator review — implemented** — suggestions can be selected, removed or supplemented; explicit correction pairs and approval are required before use.
5. **Low-latency recognition integration — implemented and guarded** — safe mode adds no Service Context prompt or hotwords. Explicit experimental assistance can add no more than two selected hints and eight additional prompt tokens. Full Bible references remain excluded; only difficult book names can use a spare experimental slot.
6. **Post-recognition hybrid — implemented** — temporary corrections are compiled once at approval, then run before the preserved layered glossary. Always-on Bible-reference formatting runs after the glossary and before caption safety, publication, transcript storage and translation.
7. **Lifecycle and cleanup — implemented** — the authoritative state is memory-only; active context locks at start, deactivates at stop, can be explicitly re-armed for four hours, and can be cleared immediately.
8. **Measurement — implemented for service comparisons** — privacy-safe reports record context mode, hint count, additional prompt-token count, Bible-reference count and correction count alongside existing decode, delay and resource measurements. They never record the terms or notes.

## Acceptance gates

- Application metadata and updater validation report `0.7.6`.
- The complete existing automated regression suite passes from the v0.7.6 source copy.
- Upgrade testing from v0.7.5 preserves operator credentials and saved settings.
- Existing captions, translations, spoken audio, OBS, Room Display, Operator, Service Leader, updater, security, and diagnostics workflows pass their applicable regression checks.
- On Windows Faster Whisper/CUDA, repeated silent pauses and sound-desk breaks resume normally without pressing Stop/Start; the service report records a restart only when callbacks actually stop, not during healthy digital silence.
- Service Context remains marked as optional and pre-service while corpus, privacy, resource and multi-platform acceptance testing continues.
- Uploaded or pasted notes never appear in logs, transcripts, diagnostics, anonymised service reports, or translated-audio output by themselves.
- Invalid, oversized, encrypted, malformed, or unsupported input fails safely without affecting the current service.
- Context preparation occurs before captions start; the optional extractor cannot contend with Whisper during a live service.
- Operators can inspect, edit, reject, approve, and clear every temporary suggestion.
- A controlled sermon corpus demonstrates a useful accuracy improvement without a material regression in false insertions, caption latency, startup time, or stability.

## Deliberately deferred until evidence supports them

- Treating a full sermon script as a live word-for-word transcript or autocue.
- Sending notes to a cloud model by default.
- Allowing generated suggestions to bypass operator review.
- Keeping sermon notes or generated temporary dictionaries indefinitely.
- Loading a second AI model during live transcription on constrained hardware.
- Promising that context will improve every speaker, accent, room, or sermon style.
